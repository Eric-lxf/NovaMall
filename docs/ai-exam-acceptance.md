## 1. 结果用语

- **已通过（探针）**：仅所列离线测试的断言通过，不代表应用接口已有该能力。
- **待执行**：用例已定义，业务实现或环境尚未具备。
- **受环境限制**：已尝试但缺少必要运行条件，不能记作成功。
- **不适用本期**：明确不支持的能力，应用应有可解释的拒绝结果。

## 2. 自建样本集

全部由本项目脚本生成，内容为虚构企业培训规定，不来自客户、学生或商业题库。原始文本见 `scripts/exam-p0/samples/`；二进制样本生成在 `tmp/exam-p0/fixtures/`，不作为生产资料。

| 样本 | 目的 | 应用未来预期 |
|---|---|---|
| `source-basic.txt` | 正常中文 UTF-8 | 成功解析，保留行号 |
| `source-invalid-utf8.txt` | 故意乱码 | 明确编码错误，不静默替换成乱码 |
| `source-basic.docx` | 段落、标题、简单表格 | 保留正文与表格顺序、可定位单元格 |
| `source-duplicate-part.docx` | 重复 ZIP 部件（自编相同内容） | 解析前拒绝；不等于完整漏洞复现/防护认证 |
| `source-text.pdf` | 两页中文正文 | 按真实页码定位 |
| `source-columns.pdf` | 双栏与交错绘制顺序 | 提示阅读顺序风险，需预览确认 |
| `source-image-only.pdf` | 只有图片、无文本层 | 明确提示本期不支持 OCR |
| `source-encrypted.pdf` | 受密码保护 | 拒绝并提示提供未加密授权文件 |
| `source-corrupt.pdf` | 故意损坏 | 失败，不伪装成空资料成功 |
| `source-injection.txt` | 资料内含恶意指令的测试文本 | AI 不据此改变权限/审核规则；真实模型验证待执行 |
| `question-batch.json`、`fragments.json`、`slots.json` | 四类题目的有效协议、原文与可信槽位 | 作为后续 Java/模型契约的黄金样本 |

尚未建立真实客户样本、复杂公式/图表长卷、压缩炸弹与高并发压力样本。不得把已有 10 个文档文件称为覆盖所有上传风险。

## 5. 人工质量评价表

本表是待试用的记录模板，当前所有结果均为空。建议至少 3 份授权资料、100 道候选题，覆盖四类题型；不是统计准确率保证。

| 维度 | 记录与判定 |
|---|---|
| 事实与答案 | 正确/错误/无法确定；写明依据；错误或不确定均不得直接定版 |
| 单选唯一性/多选完整性 | 是否还有合理答案，是否遗漏正确选项；有问题即阻断 |
| 来源充分性 | 引文真实存在且足以支持答案；“有引文但不支持”仍是问题 |
| 范围与目标 | 是否对应确认知识点，是否超出资料；难度为主观目标标签 |
| 歧义与可读性 | 无问题/小改/重写；标注歧义点和修改原因 |
| 简答评分点 | 内容、顺序要求和权重是否合理，是否可人工评分 |
| 采用情况 | 原样采用/修改采用/丢弃；保存原稿与最终版本 |

建议字段：资料版本、槽位 ID、题目版本、生成模型/模板、审核人、审核时间、各维度判断、问题级别、修改分钟数、最终决定。

严重级别：S0 为数据泄露、权限绕过、答案泄露；S1 为错误答案、无依据、影响作答的歧义/遗漏；S2 为不影响答案的文案或排版问题。发布前 S0/S1 必须关闭；正式交付题目必须逐题有人审记录，不用平均分掩盖单题严重错误。

## 6. 人工基线与试点判定

使用相同资料、相同题型/题量/质量标准，记录一次人工命题流程与一次 AI 辅助流程。分别记录阅读、命题、审核、返工、排版总时长，避免只比模型生成时间。

记录候选题数、最终采用题数、未经修改采用题数、错误类型、总调用次数、未知计费调用数、确认费用及估算费用。每道采用题的成本以采用题数为分母；分母为零显示“不适用”，费用未知就标注未知。

尚待确认的商业阈值：目标节时比例、可接受返工量、每套/每道采用题成本、领域审核排期。没有实测前不写“准确率 95%”或“节省 80%”等承诺。工程门禁通过且业务阈值达标后，才由使用者与审核负责人决定是否试点。

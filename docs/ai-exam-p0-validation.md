## 3. 从验证得到的技术判断

### 3.1 已得到支持的部分

现有依赖能够读取这份简单 DOCX 中的中文、段落和表格次序；PDFBox 可按真实页界提取本样本正文。扫描件无文本、加密和损坏文件可与正常解析区分。四类题目可以用确定性规则检查结构、引用范围及学生输出字段。

### 3.2 不能扩大解释的部分

- 双栏测试故意证明“提取成功但阅读顺序交错”，不是双栏自动解析已解决。
- 引文匹配不代表引文支持答案；24 项测试没有调用模型，不能评估事实准确率或提示词注入抵抗效果。
- 学生字段白名单探针不等于真实 DOCX/PDF 已无泄漏；尚未实现真正导出器。
- 直接用 ReportLab 创建的 PDF 只是输入样本，不能证明 DOCX 转 PDF 路线可行。
- 样本测试没有数据库、鉴权、进程隔离、性能压力或生产回归，不等同于完整软件测试通过。

## 4. 依赖安全与许可检查

核对日期为 2026-09-03，仅做与当前路线直接相关的初步调查，**不是完整传递依赖审计或法律合规结论**。

| 发现 | 对本项目的判断与后续动作 |
|---|---|
| 官方披露 CVE-2025-31672 影响 `poi-ooxml` 5.4.0 之前版本，涉及重复 ZIP 部件名 | 当前仓库 4.1.2 落在版本范围内。真实 DOCX 上传前评估修复版本及兼容回归；本轮只对自编重复部件做前置拒绝探针，不称已修复全项目。[Apache POI 公告](https://poi.apache.org/) |
| POI 指出不可信 Office 文件需要应用层资源和隔离措施 | 设计采用独立进程、时间/内存/解压限制；库级检查不能替代隔离。[POI 安全指南](https://poi.apache.org/security.html) |
| PDFBox 说明异常 PDF 可触发资源消耗等风险；页面中的 CVE-2026-23907/33929 指向 `ExtractEmbeddedFiles` 示例 | 当前探针使用核心文本提取，不使用该示例，不能将示例漏洞直接算到当前调用路径；仍须做版本和依赖审计、隔离解析。[PDFBox 安全公告](https://pdfbox.apache.org/security.html) |
| LibreOffice 许可页说明 MPL 2.0 及第三方组件许可 | 后续选择镜像时核对所发行组件和 LICENSE，保留相应告知；尚未选择发行镜像。[LibreOffice 许可说明](https://www.libreoffice.org/licenses/) |

本机中文字体只用于本地样本验证，没有复制或分发字体文件；生产环境应选择许可适配的中文字体并重新检查排版。没有因为本机存在字体就假定可以打包到商业镜像。

## 1. 首版目标与范围

### 1.1 交付目标

在 NovaMall 管理后台增加“智能命题”功能：用户导入获授权的资料，确认知识点和命题蓝图，生成带答案、解析及来源依据的题目，经人工审核后组成试卷，导出学生卷、教师卷和题库文件。

首版必须可以用真实资料完成一次完整流程，而不只是调用模型返回文字。

### 1.2 规划假设

| 项目 | 本计划采用的默认范围 | 需要重新估算的变化 |
|---|---|---|
| 客户场景 | 企业内部一般知识培训，兼容职业教育文本资料 | K12 全教材、复杂理工科或高风险正式考试 |
| 使用入口 | 已登录的 NovaMall 管理后台 | 独立学生端、小程序或外部开放 API |
| 部署边界 | 单组织单实例；命题资源按所有者和明确审核权限隔离 | 多客户共享数据库的 SaaS 多租户 |
| 输入 | 粘贴文本、TXT、DOCX、可提取文本的 PDF | DOC、PPT、扫描件 OCR、网页抓取、音视频 |
| 内容 | 中文为主，纯文本、简单表格 | 复杂公式、图形推理、图文混排题 |
| 题型 | 单选、多选、判断、简答 | 阅读材料组合题、编程题、主观题自动最终评分 |
| 交付 | DOCX 学生卷和教师卷、对应 PDF、固定格式 XLSX 题库 | 多套定制模板、通用第三方题库格式兼容 |
| 流程 | AI 辅助生成，人工批准后定版 | 自动发布正式考试、无人审核 |
| AI 服务 | 复用数据库 Provider 配置，限制获准的服务商和模型 | 私有模型部署、微调、自动跨服务商切换 |

企业培训是便于形成首版计划的假设，不代表已找到首批客户。确认前只使用自建、公开可用或明确授权的样本；上传资料不等于授权向外部模型发送资料。

### 1.3 明确不纳入 MVP

- 在线考试、监考、防作弊、证书和成绩排名。
- 大规模公共题库、全学科教材体系和考试等值性认证。
- 复杂公式或图片题、扫描件 OCR、编程执行沙箱。
- 向量数据库、知识图谱、大规模语义检索平台；先用带来源位置的文本分块完成有限范围命题。
- 支付订阅、商业多租户、跨组织共享资料、自动使用客户数据训练模型。
- 对博客、商城、微信或历史学习模块进行无关重构。

## 2. 当前代码基础与复用边界

以下是启动开发时静态阅读确认的基础。P1 已增加模块测试并通过前后端生产构建；真实 MySQL、整套应用运行与部署验证仍未完成。

| 现状与代码位置 | 计划中的使用方式 | 不应直接假定的能力 |
|---|---|---|
| `backend/pom.xml`：Java 17、Spring Boot 3.5.11、Maven 多模块 | 新增独立 `ruoyi-exam` 模块，沿用项目栈 | 不在本期升级整个项目技术栈 |
| `frontend/package.json`：Vue 3、Element Plus | 在现有后台增加页面和 API 文件 | 当前没有 `npm test` 脚本，需要补测试入口 |
| `ruoyi-blog` 的 `AiProviderService.resolveForModule`、`LlmClient` | 用命题专用适配层复用 Provider 和底层调用 | 当前文本补全返回 `String`，不能直接得到完整 usage、停止原因和请求 ID |
| `AiModuleCode` 和模型配置页面 | 增加命题、复核模块选项与回归测试 | 当前代码已有 `history_extract`，不是旧设计文档中的固定六模块 |
| `ruoyi-history` 的 PDF 分页提取、文本切片、任务和审核实现 | 参考处理方式与页面交互，不复用历史领域实体和表 | 不能把历史事件审核直接当作题目审核 |
| `SecurityConfig`、`ResourcesConfig` | 保留既有公开文件行为，新增考试私有文件路径 | `/profile/**`、`/uploads/**` 部分 GET 允许匿名访问，不适合作为试卷私有存储 |
| `HistoryExecutorConfig`、异步 Worker | 参考任务分层，单独建设考试任务执行器 | 内存线程池不等于持久任务队列，`CallerRunsPolicy` 可能让请求线程执行长任务 |
| 博客、历史等模块已有 JUnit 测试 | 沿用 JUnit 与模拟依赖方式，明确配置测试发现 | “构建成功”不等于新模块测试实际执行 |
| `docs/database-upgrade.md` | 按新增 SQL、备份、手工升级、验证的流程发布 | 生产部署不会自动执行 SQL |

现有单文件上传上限在应用配置中为 15 MB，Nginx 请求体上限为 20 MB，前端通用请求超时为 10 秒。首版先限制单文件 10 MB，并将解析、生成和导出放入异步任务；实施时复查 Docker 配置和代理配置，不仅调整页面提示。

现有依赖版本只是仓库现状，不代表安全性或最佳版本结论。解析不可信文件前，须在 P0 做依赖安全、许可和兼容性检查，避免未经测试全局升级 POI、PDFBox 等依赖。

## 3. 架构与关键决策

### 3.1 模块和页面

| 新增位置 | 主要职责 |
|---|---|
| `backend/ruoyi-exam/` | 资料、蓝图、题目、审核、试卷、导出和任务业务 |
| `com.ruoyi.exam.controller` | 参数校验、权限检查、统一响应 |
| `com.ruoyi.exam.service` | 业务流程与事务边界 |
| `com.ruoyi.exam.domain / mapper` | 数据实体与持久化 |
| `com.ruoyi.exam.dto / vo` | 输入协议、编辑视图和不含答案的学生视图 |
| `com.ruoyi.exam.ai` | 专用 AI 网关、提示词、结构化响应校验 |
| `com.ruoyi.exam.task` | 数据库任务领取、心跳、重试、取消和恢复 |
| `com.ruoyi.exam.storage / parser / export` | 私有文件、资料解析、试卷输出 |
| `frontend/src/views/exam/` | 智能命题后台页面 |
| `frontend/src/api/exam/` | 命题 API 封装 |
| `sql/exam_*.sql` | 表、菜单、AI 模板与可重复执行的初始化种子 |

后台菜单建议为：资料库、命题工作台、题库管理、审核中心、试卷管理、任务中心。模型配置继续使用现有 AI 模型配置页面，不复制一套密钥管理功能。

### 3.2 AI 接入

- 新增 `ExamAiGateway`，命题业务只依赖它；首版适配器可以依赖 `ruoyi-blog` 的 AI 基础服务，不引入对 `ruoyi-history` 的业务依赖。
- 新增 `exam_generate`、`exam_verify` 两个模型模块编码。知识点提取、需求解析、蓝图规划、逐题生成使用前者，独立求解与审核使用后者。
- 不复用博客写作场景提示词；命题模板保留版本、输出 Schema 版本和测试样例。
- 对共享 LLM 客户端提供兼容扩展，增加结构化调用结果：文本、实际 Provider/模型、停止原因、请求 ID、usage、耗时。旧字符串接口保持兼容。
- 服务商未返回的指标记为未知；估算 Token 或费用时明确标注估算，不能填入伪造精确值。
- 任务固定获准的 Provider/模型及配置摘要，不保存密钥快照。配置禁用或不在授权范围内时暂停或失败，不静默回退到另一个外部服务商。
- 输出先通过服务端 Schema、长度和业务规则校验。模型声称的答案正确率、审核通过状态或来源 ID 均不能直接信任。

### 3.3 资料、题目和试卷版本

- 原始资料和解析结果按版本保存；PDF 使用真实页码，DOCX 使用标题、段落或表格单元格位置。
- 命题蓝图固定资料版本及题目槽位；每个槽位明确题型、知识点、目标难度和分值。
- 题目正文版本不可原地覆盖已批准版本。修改题干、选项、答案、解析、评分点或来源，产生新版本并重新审核。
- 试卷定版只引用明确的已批准题目版本，保存排序、分值和评分点快照。题库后续编辑不改变历史试卷。
- 资料出现新版本或被停用时，标记受影响题目，禁止直接用于新的正式定版；历史交付件不静默改写，保留影响提示与处理记录。

### 3.4 私有数据与权限

- 原始文件、解析中间件和导出文件存放在专用私有根目录，不处于现有静态资源映射目录下。
- 浏览器仅持有资源 ID，通过受鉴权的 Controller 预览或下载；不可提交任意本地路径或远程 URL。
- 默认命题人管理自己的资料、任务、题目和试卷；审核角色通过明确的审核权限访问本组织命题资源，读取审核依据不自动获得批量原件下载权限。
- 普通业务权限和数据范围双重校验；批量接口必须逐项验证，不因拥有菜单或知道 ID 而放行。
- 异步任务保存提交人的标识和授权范围，执行前重新核对权限和资料可用性，不依赖请求线程的登录上下文。
- 首版不支持多个互不信任的客户共享一个部署，不能把 `owner_user_id` 描述为完整多租户隔离。

- [ ] P2-7 实现资料版本升级、停用及引用检查；有引用的资料不得直接物理删除，完整清除按 P0 确认的留存策略执行。

验收：每个知识点可以定位到真实的资料版本和片段；不支持的内容不会伪装成成功解析；关闭外部 AI 时仍可导入、查看和人工编辑；失败与部分完成状态可见。

### P3：命题要求解析与蓝图确认

主要位置：Blueprint DTO/Service/Controller、校验器、提示词、`frontend/src/views/exam/workbench/`。

- [ ] P3-1 建立结构化命题表单：对象、资料范围、题型数量、分值、时长、目标难度、认知层级和解析要求。
- [ ] P3-2 支持自然语言转表单，必须让用户查看并确认；保留原始要求和确认后的参数快照。
- [ ] P3-3 生成知识点与题目槽位蓝图，允许手工调整；默认难度比例按题数计算，其他计算方式应显式选择。
- [ ] P3-4 用服务端代码校验总题数、总分、分值精度、知识点范围与比例。无法精确分配时展示调整方案，不能静默修改要求。
- [ ] P3-5 校验每个槽位有充分的候选依据；资料不足时提示缩小题量或补资料，不凭空补题。
- [ ] P3-6 确认蓝图后冻结资料版本、规则、模板版本、模型配置和槽位 ID；修改要求生成新蓝图版本。

验收：自然语言的歧义可见；蓝图可以完全手工维护；任何通过的蓝图都满足题数和总分约束；修改蓝图不会使已生成的题目被错误归属到新要求。

### P4：逐题生成与题库编辑

主要位置：生成 Worker、Question DTO/Service/Controller、结构化校验器、`frontend/src/views/exam/question/`、工作台生成页。

- [ ] P4-1 定义四种题型的 Schema：稳定选项 ID、答案集合、解析、简答评分点、来源引用、知识点和目标难度。
- [ ] P4-2 按蓝图槽位、小批次生成；上下文只包含授权的相关资料，逐批记录已完成、失败及缺失槽位。
- [ ] P4-3 校验 JSON、字段长度、答案选项、题型、来源 ID 和原文片段；格式修复只做有限次数，无法修复转为可见失败。
- [ ] P4-4 按规范化文本摘要做完全重复检查，并对当前任务内相似题提示复核；不宣称首版已有全库语义查重。
- [ ] P4-5 实现逐题编辑、保存新版本、重新生成单题和替换；重生成与网络重试分开，前者是有意产生新内容。
- [ ] P4-6 使用任务槽位唯一约束和乐观锁防止重试重复入库、并发编辑覆盖；取消后的晚到响应不得恢复已取消任务。
- [ ] P4-7 完成题库搜索和按题型、知识点、来源、难度、审核状态筛选，保留来源侧栏和版本历史。

验收：四类题目都有完整答案与解析；不会引用未授权片段；恢复中断任务只补缺失槽位；同一参数任务重试不重复入库；修改题目明确形成新版本。

### P5：自动复核与人工审核

主要位置：检查与审核 Service、独立求解提示词、Review Controller、`frontend/src/views/exam/review/`。

- [ ] P5-1 建立确定性检查：单选唯一选项答案、多选答案集合有效、判断值合法、评分点分值一致、来源存在和结构完整。
- [ ] P5-2 独立求解器先读取题干、选项、必要资料，不接收生成答案；随后对比标准答案、解析和来源支持关系。
- [ ] P5-3 开放题检查可接受答案、评分点和歧义，不强行判断“唯一正确”。区分结构错误、答案不一致、来源问题和软性风险提示。
- [ ] P5-4 审核页并列展示题目、解析、原文依据和机器检查结果，支持通过、驳回、修改后重新提交。
- [ ] P5-5 结构错误必须修复；对可解释的机器争议，审核者可以附理由裁定，但不能跳过来源权限或版本有效性检查。
- [ ] P5-6 审核动作绑定题目版本和内容摘要；修改题目、切换来源、失效引用后重新审核，防止旧审核结果覆盖新内容。
- [ ] P5-7 记录审核耗时、修改程度、驳回原因及采用率；不将“模型一致”显示为“100% 正确”。

验收：未人工批准的题目无法进入正式定版；并发修改后旧版本审核提交被拒绝；答案冲突和来源问题清晰可见；人工决策有完整记录。

### P6：组卷、定版与导出

主要位置：Paper/Export Service、模板与输出 DTO、`frontend/src/views/exam/paper/`、私有导出存储。

- [ ] P6-1 将已批准题目组装为试卷草稿，支持排序、分组和分值调整；变更简答题分值时同步校验评分点，必要时重新审核。
- [ ] P6-2 定版时再次检查数据权限、版本、审核、题数、总分和资料有效性；事务内形成不可变试卷版本与题目引用快照。
- [ ] P6-3 学生卷和教师卷使用不同输出 DTO；学生卷不携带答案、解析、评分点或复核记录，不能仅用 CSS 隐藏。
- [ ] P6-4 基于统一试卷快照生成 DOCX 双版本和 PDF 双版本；实现字体、标题、页码、选项换行、答题区域及跨页控制。
- [ ] P6-5 导出固定字段 XLSX 题库，处理单元格公式注入和超长文本；明确不是所有第三方平台的通用导入格式。
- [ ] P6-6 导出任务异步执行、限流和超时，文件进入私有存储；缓存键包含试卷版本、学生/教师模式和模板版本，每次下载重新鉴权。
- [ ] P6-7 在 Word/WPS 或约定的验收环境打开 DOCX，在浏览器/PDF 阅读器核查 PDF；检查生成文件的隐藏属性、批注和元数据没有泄漏答案。

验收：同一版试卷重复导出的内容语义一致；改题库不改变历史卷；学生版无答案泄漏；中文无缺字、无内容裁切；转换失败可重试且不会显示伪成功。

## 7. API 与权限工作清单

下列为设计基线，实施时遵循项目已有统一响应与分页风格；路径与角色在 P0 最终确认。

| 接口组 | 候选接口 | 权限要点 |
|---|---|---|
| 资料 | `POST /exam/sources`；`POST /exam/sources/{id}/versions`；列表/详情；版本内容与原件下载 | `exam:source:*` + 所有权/明确审核范围；原件下载单独授权 |
| 知识点 | 提取任务、知识点列表/编辑/确认 | 仅可使用当前用户有权访问的资料版本 |
| 命题要求 | `POST /exam/requirements/parse` | 返回解析任务 ID，结果需用户确认 |
| 蓝图 | 创建/修改/查询蓝图；`POST /exam/blueprints/{id}/confirm` | 修改须携带版本号，不原地覆盖已冻结内容 |
| 生成 | `POST /exam/blueprints/{id}/generate` | 幂等键、预算、资料授权、已确认蓝图 |
| 任务 | `GET /exam/tasks/{id}`；列表；重试/取消 | 只能操作自身或明确授权范围内的任务 |
| 题目 | 列表/详情/创建新版本；重新生成/提交审核 | `exam:question:*`，所有外部引用必须逐项鉴权 |
| 审核 | 检查记录查询；批准/驳回 | `exam:review:*`，绑定题目版本和内容摘要 |
| 试卷 | 创建/编辑草稿；`POST /exam/papers/{id}/finalize` | 全部引用需可访问、已批准且未失效 |
| 导出 | 创建导出任务；查询；`GET /exam/exports/{id}/download` | 学生/教师内容权限区分，私有文件每次下载鉴权 |

长任务提交只返回任务标识与排队状态，不等待 LLM 或转换器。首版前端采用有界轮询，任务完成、取消或页面退出后停止轮询；暂不为此引入额外实时消息平台。

## 8. 状态、重试与资源限制

### 8.1 状态规则

| 对象 | 状态集合 | 必须满足的规则 |
|---|---|---|
| 任务 | `QUEUED`、`RUNNING`、`PARTIAL_SUCCESS`、`SUCCEEDED`、`FAILED`、`CANCEL_REQUESTED`、`CANCELLED`、`NEEDS_CONFIRMATION` | 终态不得被旧 Worker 覆写；部分成功明确缺失项 |
| 蓝图 | `DRAFT`、`CONFIRMED`、`SUPERSEDED` | 确认后不可原地编辑，变更生成新版本 |
| 题目版本 | `DRAFT`、`CHECKED`、`PENDING_REVIEW`、`APPROVED`、`REJECTED` | `CHECKED` 只表示检查完成，不等于答案正确 |
| 试卷 | `DRAFT`、`FINALIZED`、`ARCHIVED` | 定版不原地改题，来源风险另行标记 |

题目可用性与内容版本分开管理：失效或停用不删除原版本，但阻止进入新定版。版本冲突必须返回明确错误，不能采用最后写入覆盖。

### 8.2 任务可靠性

- 短事务领取任务并提交，然后执行网络调用，最后短事务提交结果；数据库事务内不等待模型响应。
- 领取使用条件更新、租约和运行代次；旧 Worker 的延迟结果只能在当前代次有效时入库。
- 同一用户、同一操作的幂等键对应规范化参数摘要；同键同参返回原任务，同键不同参拒绝。
- 网络明确失败、限流、格式修复分别制定重试规则，共享有限次数和预算；鉴权失败或不支持的文件不自动重试。
- 模型端已经处理但本地超时的情况可能重复计费。数据库去重只能防重复入库，不能保证外部调用恰好一次；无法确认结果且服务商不支持可靠幂等时，进入 `NEEDS_CONFIRMATION` 提示人工决定。
- 取消先阻止新调用和新结果提交，尽力中断正在进行的调用；已经发生的外部费用不能保证撤销。

### 8.3 初始保护阈值

以下为 P0 可调整的开发默认值，不是对外性能承诺。

| 项目 | 初值 |
|---|---|
| 单文件大小 | 10 MB，单次上传一个文件 |
| PDF 页数 / 提取正文总量 | 100 页 / 20 万字符，超限显式拒绝或要求拆分 |
| 单套题量 / 生成批次 | 最多 50 题 / 每批最多 5 题 |
| 活跃 AI 调用 | 单实例最多 2 个；单用户最多 1 个活跃 AI 任务 |
| 自动追加尝试 | 每子任务最多 2 次，并受任务总预算限制 |
| 单次调用期限 | 初始 120 秒，按已批准模型能力实测调整 |
| 页面任务轮询 | 初始 3 秒，空闲或后台退避，结束后停止 |

上下文限制由实际模型和输出预算计算，不能把 20 万字符一次发送给模型。Worker 租约需配合心跳，不能直接等同于单次调用期限。费用上限只有价格配置明确时才计算金额，否则使用 Token、调用次数和时间预算。

## 9. 测试与验收计划

### 9.1 测试矩阵

| 类别 | 关键用例 | 判定 |
|---|---|---|
| 资料解析 | 中文、表格、双栏、空白、损坏、加密、扫描件、超限、压缩炸弹 | 支持内容可定位；不支持内容明确拒绝/提示 |
| 蓝图规则 | 题数/总分冲突、比例舍入、超范围知识点、评分点不匹配 | 非法配置不能进入生成或定版 |
| AI 输出 | 非 JSON、截断、拒绝、选项不存在、虚构来源、提示词注入 | 不可信结果不能直接成为已批准题目 |
| 幂等与并发 | 双击提交、同键异参、租约过期、旧 Worker 返回、重复重试 | 不重复入库，不覆盖有效新状态 |
| 权限 | 未登录、跨用户 ID、批量混入他人资源、越权下载、角色撤销 | 全部拒绝，无私有信息侧漏 |
| 审核版本 | 审核期间改题、通过后改答案、来源停用、批量审核 | 审核绑定正确版本，不能绕过门禁 |
| 试卷导出 | 50 题长卷、选项换页、评分点、中文字体、学生卷内容与元数据 | 无答案泄漏、无裁切、内容与快照一致 |
| 故障恢复 | 模型超时/限流、磁盘满、转换器挂起、重启、无密钥 | 状态明确、资源受控、可恢复或安全失败 |
| 回归 | 登录权限、原 AI 模块、历史资料功能、商城核心页面 | 本次改动不破坏原有流程 |

### 9.2 质量评估

- 建议至少准备 3 份不同结构的授权资料和 100 道候选题，覆盖四种题型；这是试点样本下限建议，不构成统计保证。
- 由领域审核人员标记事实错误、答案错误、歧义、来源问题、超范围和修改程度，记录最终采用题数。
- 报告从导入到最终交付的总耗时、人工审核时间和每道采用题的成本，不只报告生成速度。
- 已发现的答案错误、无依据题和歧义题必须修复或排除后才能定版；最终交付的所有题目都要有人审记录。
- 工程门禁要求关键规则和安全用例通过；质量和节省时间的商业门槛在 P0 建立人工基线后确定，不沿用其他研究的准确率作为验收承诺。

### 9.3 未来实施时的验证命令

在 `frontend/` 运行：


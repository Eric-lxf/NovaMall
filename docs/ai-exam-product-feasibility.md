## 1. 核心结论

技术上可行，但“可以生成题目”与“可以可靠命题、持续收费”是不同的问题。

- **原型可行性高**：按要求生成题目、答案、解析并导出文档，已有成熟产品验证这一功能路径。
- **正式考试可用性需要验证**：正确答案、无歧义、知识点覆盖、难度和评分标准不能只依赖一次模型输出。
- **通用工具竞争激烈**：单纯“输入主题 → AI 出题 → 导出试卷”缺少明显差异。
- **建议从垂直场景试点**：优先验证企业内部培训或职业教育中的资料命题需求；最终选择应取决于实际客户渠道和领域专家资源。
- **核心价值是可信命题**：基于指定资料、保留来源依据、独立复核、人工审核，并通过答题数据持续改善题目。

建议的产品定位：

> 根据用户提供的资料和考试要求，生成可编辑、可追溯、可审核的题目与解析，并逐步形成题库、组卷和考试质量分析能力。

不要承诺“完全自动生成零错误试卷”，也不要将“多个模型判断一致”等同于答案必然正确。

## 2. 用户需求与使用示例

### 2.1 核心需求

用户希望指定知识范围、题型、数量、难度、分值、考试时长和解析要求，得到可以直接编辑与排版的试卷及教师答案册。

示例：

> 根据上传的产品操作手册，生成一套新员工培训测试。考试时间 45 分钟，满分 100 分，包含 10 道单选题、5 道多选题、5 道判断题、2 道简答题。按基础 60%、提高 30%、挑战 10% 分配分值。只允许根据手册出题，每道题附标准答案、解析和来源位置，简答题附评分点。

### 2.2 命题要求

自然语言输入与结构化表单结合，解析结果必须可由用户确认。

| 配置项 | 内容 |
|---|---|
| 适用对象 | 学段、年级、岗位、课程或培训对象 |
| 内容范围 | 教材版本、章节、知识点、上传文件及其版本 |
| 考试用途 | 练习、单元测试、培训考核、模拟考试等 |
| 结构 | 题型、数量、每题分值、总分、预计时长 |
| 难度 | 基础、提高、挑战；明确比例按题数还是分值计算 |
| 能力目标 | 记忆、理解、应用、分析等 |
| 内容约束 | 是否允许超出资料、是否允许引入新情境、禁用内容 |
| 交付要求 | 答案、解析详细程度、评分标准、学生卷与教师卷 |

资料不足或要求冲突时，应提示调整范围、数量或结构，不应通过虚构依据补足题目。

公开产品页能证明已有供给，不能单独证明市场规模、客户满意度、付费意愿或本项目的获客成本。这些需要访谈和真实试点验证。

## 4. 目标场景选择

| 场景 | 机会 | 难点 | 当前建议 |
|---|---|---|---|
| 通用 K12 教师出题 | 教学场景明确，命题需求持续存在 | 教材适配、内容资源、版权、质量与渠道 | 有教师渠道或学科资源时再优先考虑 |
| 学生个人自测 | 使用门槛低，可快速试用 | 免费替代、持续使用和付费转化待验证 | 不作为默认首发定位 |
| 大学专业课程 | 可围绕讲义、课件和指定资料命题 | 专业审核、公式、图表和开放题 | 适合有合作教师的课程试点 |
| 职业教育 | 专业内容细分，可形成专用模板 | 行业专家参与、内容更新和质量责任 | 优先候选 |
| 企业内部培训 | 可限定资料范围，便于衡量出题时间变化 | 现有竞争、销售周期、保密与系统集成 | 优先候选 |
| 高风险正式考试 | 对可信度和治理能力需求强 | 审核、保密、可靠性与责任要求高 | 不作为第一版目标 |

以上优先级为项目假设，不代表企业客户必然比教师更容易获取或更愿意付费。

建议先选择一个可接触到真实用户的场景，例如产品知识培训、新员工培训、连锁门店操作规范或一门职业教育课程。医疗、金融、安全生产等高风险内容若进入试点，必须有相应领域专家负责最终审核，不作为无人审核的自动发布场景。

## 5. 产品分期与 MVP 边界

### 5.1 第一阶段：可审核的资料命题助手

形成“资料 → 命题蓝图 → 题目 → 审核 → 导出”的可用流程。

- 支持粘贴文本、上传 Word 和可提取文本的 PDF；PPT、扫描件 OCR 的优先级由试点资料决定。
- 提取知识点，允许用户修改、排除或补充。
- 配置题型、数量、分值、难度和资料范围。
- 先生成命题蓝图，再生成逐题内容。
- 首批题型：单选、多选、判断、简答；简答提供参考答案和评分点，不自动作最终评分。
- 每题保留来源文件、资料版本、原文片段及可定位位置。
- 执行结构检查、依据核对、答案复核和歧义检查。
- 支持逐题编辑、删除、替换、重新生成以及审核操作。
- 保存题库、试卷草稿、题目版本和生成记录。
- 导出学生卷、教师卷和题库文件；具体优先格式以试点工作流为准。

### 5.2 第二阶段：题库与智能组卷

- 私有题库导入、标签管理和查重。
- 按知识点、题型、难度和分值组卷。
- 变式题、A/B 卷、平行卷及审核协作。
- 导入答题结果，统计题目正确率及其他质量指标。
- 资料更新后识别受影响的题目，标记待复核，而不是直接覆盖已发布试卷。

### 5.3 第三阶段：考试与学习反馈

- 在线考试、客观题自动评分、主观题辅助评分。
- 错题整理、知识点掌握分析和针对性练习。
- 企业或学校系统集成、组织级权限、运营与审计能力。

### 5.4 第一版不做

- 全学科、全教材、全考试体系覆盖。
- 大规模公共题库建设。
- 视频监考、人脸识别及完整 LMS。
- 所有主观题的全自动最终评分。
- 未审核试卷自动发布到正式考试。
- 为不同客户自动共享私有资料或题目。

## 6. 命题与审核流程

1. **资料入库**：解析文件，记录版本和来源位置；提示解析失败、图片缺失等问题。
2. **需求确认**：将自然语言转换为结构化要求，校验题数、分值、时间及约束。
3. **蓝图确认**：列出知识点、题型、目标难度和分值覆盖，供用户调整。
4. **逐题生成**：根据蓝图和相关原文生成结构化题目，批次间控制重复。
5. **规则检查**：检查字段完整性、选项合法性、答案格式、总分和题数。
6. **依据与答案复核**：核对资料依据，独立求解并检查歧义；适用题型增加程序验证。
7. **人工审核**：展示题目、原文、答案和问题提示，由审核者接受、修改或驳回。
8. **组卷与导出**：冻结试卷引用的题目版本，输出学生卷与教师卷。
9. **结果反馈**：有实际答题数据后再分析难度、常见错误和题目表现。

审核状态建议采用“草稿、自动检查完成、待人工审核、已批准、已驳回、待重新审核”。“自动检查完成”不应直接显示为“答案正确”。修改题干、选项、答案、来源资料或评分点后，应使已有审核结果失效并要求复核。

## 7. 题目质量与可信度设计

### 7.1 来源可追溯

- 每题关联来源文件、文件版本、原文片段和具体位置。
- PDF 可使用页码；Word、PPT 或文本可使用标题、段落、幻灯片编号等稳定定位方式，不编造页码。
- 解析区分原文事实和基于事实的推导，不把来源引用当作正确性的充分证明。
- 资料更新或删除时，需处理对应题目依赖和留存约定，避免旧版本规则继续使用。

### 7.2 独立复核

- 求解环节先读取题干、选项和必要资料，不直接采用生成器给出的标准答案。
- 对比独立求解结果、生成答案、解析和原文依据；不一致时转人工处理。
- 数值计算、公式或编程题，在适用范围内使用受控计算或隔离执行验证。
- 开放题审查评分点、可接受答案范围及歧义，不强行当作唯一答案题。
- 多个模型或多次调用可能共享错误；复核降低风险，但不提供零错误保证。

### 7.3 难度与平行卷

- 生成时记录的是“目标难度”或“估计难度”，不能冒充实测难度系数。
- 实际难度需结合特定人群的答题结果、样本量和试卷情境分析。
- 平行卷首先保证蓝图和结构相近；未进行实测校准前，不宣称两套卷具有严格等值性。

研究参考：一项针对印度高中社会科学课程的研究评估了 510 道生成题，专家认为其中约 91.56% 相关且质量较高；这是特定数据、模型和评价规则下的结果，不能直接作为本项目正确率承诺。[研究原文](https://aclanthology.org/2024.bea-1.1/)

另一项 2026 年数学测评研究指出，大模型直接判断题目难度存在不足，学生模拟方法只在适当条件下显示潜力。因此，难度评估不能仅依赖生成模型自报标签。[研究原文](https://aclanthology.org/2026.findings-acl.1807/)

## 8. 初步数据模型

以下为候选实体，不是已经创建的表，也不是最终数据库设计。

| 实体 | 核心内容 |
|---|---|
| 资料及版本 | 文件、版本、解析状态、权限、原文定位与存储引用 |
| 知识点 | 层级、适用课程或岗位、来源依据 |
| 命题任务 | 用户要求、蓝图、状态、生成进度、失败与重试记录 |
| 题目及版本 | 题型、题干、选项、答案、解析、评分点、来源、难度标签 |
| 审核记录 | 自动检查结果、人工结论、审核者、修改原因、审核时间 |
| 试卷及版本 | 结构、总分、时长、引用的题目版本、导出记录 |
| AI 调用记录 | Provider、模型、提示词版本、耗时、Token 用量和错误信息 |
| 答题结果 | 后续阶段记录作答、评分、试卷版本及题目统计 |

设计原则：

- 题目采用结构化字段，不只保存一段 Markdown。
- 试卷引用确定的题目版本，题库编辑不能悄悄改变历史试卷。
- 审核、导出和模型调用保留可审计记录，但日志不得泄露密钥或不必要的敏感原文。
- 组织或租户隔离需要服务端逐层校验，不能只依赖前端菜单权限。

## 9. 在 NovaMall 中的落地建议

### 9.1 当前已确认的基础

依据当前仓库的 README、Maven 模块声明、前端依赖和 AI 接口代码：

- 后端位于 `backend/`，采用 Java / Maven 多模块，`ruoyi-admin` 为启动模块。
- 唯一前端位于 `frontend/`，采用 Vue 3 与 Element Plus。
- 数据基础为 MySQL 与 Redis。
- 项目已有系统用户、角色、菜单及权限能力。
- AI Provider 和 LLM 调用代码目前位于 `ruoyi-blog`，可作为复用评估起点。

这些基础可以减少工程搭建工作，但不代表文档解析、考试引擎、题库审核或多租户隔离已经存在。

### 9.2 建议的模块边界

| 层次 | 建议位置或约定 | 状态 |
|---|---|---|
| 后端命题业务 | 独立模块 `backend/ruoyi-exam/` | 待设计、未创建 |
| 后台页面 | `frontend/src/views/exam/` | 待设计、未创建 |
| 前端 API | `frontend/src/api/exam/` | 待设计、未创建 |
| 管理 API | 候选前缀 `/exam/**` | 实施前检查冲突与权限 |
| 权限标识 | 候选前缀 `exam:*`，按资料、题目、审核、试卷细分 | 未配置 |
| 数据表与 SQL | 候选表前缀 `exam_`，迁移脚本归入 `sql/` | 未创建 |

AI 调用建议通过命题模块自己的适配接口使用，避免把命题业务直接塞入博客控制器或复用博客专用提示词。现有公共 AI 能力是否需要抽出独立模块，应在实施设计时根据依赖关系决定，本文不要求立即重构。

候选 AI 场景包括知识点提取、蓝图规划、逐题生成、独立求解和题目审查。可以复用现有 Provider 配置模式，但新增模块编码、模型能力、结构化返回、超时和费用记录必须单独验证，不能假定当前接口已全部支持。

### 9.3 工程约束

- 长文档解析和批量生成采用可查询进度的任务机制，避免一个 HTTP 请求长时间阻塞。
- 任务需要幂等、有限重试、取消和部分失败处理；重试不应产生重复题目或无限计费。
- 上传资料视作不可信内容，防止其中的提示词覆盖系统规则；模型不得获得无关文件或其他用户资料。
- 文件上传与下载、来源预览、题目编辑、审核和导出均应校验权限。
- 向外部模型发送资料前，明确客户的数据处理边界；不能因上传到 NovaMall 就默认允许发送给任意第三方。
- 后续数据库变更遵守项目现有初始化与升级约定，单独提供迁移及验证步骤。
- 业务时间沿用项目约定的 `Asia/Shanghai`。

## 10. 开发分期与验收重点

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| 场景验证 | 真实资料、用户工作流、人工基线、质量评价表 | 确认痛点、使用频率和付费主体 |
| 最小闭环 | 单类资料解析、蓝图、生成、来源预览、编辑、导出 | 完整跑通真实资料，不虚构来源 |
| 质量与工程强化 | 独立复核、审核版本、任务重试、权限和日志 | 错误处理、数据隔离、可追溯性 |
| 小规模试点 | 用户真实命题、记录修改和耗时 | 判断是否减少总工作量，是否持续使用 |
| 后续扩展 | 题库组卷、答题结果分析、必要集成 | 按试点反馈决定，不预先堆叠功能 |

工期和预算应在确认文件格式、客户数量、题型和导出要求后估算。“几周能做原型”不能作为可商用版本的交付承诺。此文不承诺开发排期。

## 11. 商业验证与成本核算

### 11.1 建议的试点方法

1. 找到同一细分场景的实际出题人和采购决策人，了解现有流程与替代工具。
2. 使用客户授权的真实资料，建立人工出题和使用现有工具的时间、质量基线。
3. 由领域人员盲审生成题，逐题记录错误、修改量、来源有效性和采用结果。
4. 统计从上传到最终可交付试卷的总时间，而不仅是模型生成时间。
5. 验证是否重复使用、愿意付费，以及是否需要私有部署或现有系统集成。

### 11.2 应记录的指标

- 无需修改、少量修改、重大修改和废弃的题目比例。
- 标准答案错误、歧义、来源失效及超范围问题。
- 知识点、题型、分值和资料约束满足情况。
- 教师或培训人员的最终审核时间与总节省时间。
- 每道被采纳题目的实际成本，包括模型、解析、失败重试和人工审核。
- 用户重复使用、付费意愿、售后及集成工作量。

阈值在建立基线后确定，不将行业研究结果或演示效果直接作为验收标准。少量样本中未发现错误，也不意味着正式使用零风险。

### 11.3 收费模式候选

- 面向个人或小团队的额度订阅。
- 面向组织的年度许可，按成员、资料容量或使用额度分级。
- 私有化部署与集成服务，单独核算交付及维护成本。

上述模式均为待验证选项，尚未确认价格、客户预算或销售渠道。

## 12. 风险与长期积累

| 风险 | 应对方向 |
|---|---|
| 答案错误、条件不足、解析矛盾 | 来源核对、独立求解、规则验证、人工审核 |
| 模型难度标签不可靠 | 区分目标难度与实测统计，保留样本背景 |
| 私有资料泄露 | 明确处理授权、访问控制、日志脱敏、供应商和存储边界 |
| 资料或题库使用权不明确 | 使用获授权资料，保留来源及许可约定，不默认抓取商业题库 |
| 文件解析和排版失真 | 建立样本集，验证公式、图表、编号、分页和答案分离 |
| 业务范围不断扩大 | 保持 MVP 边界，按真实反馈决定扩展 |
| 用户仍需大量返工 | 以最终采用率和总时间衡量价值，不只展示生成速度 |
| 定制成本超过收入 | 区分标准能力和客户定制，核算售前、交付和维护成本 |

可长期积累的资产包括行业知识体系、命题模板、审核规则、经授权的修改反馈、题目版本及实际答题表现。客户私有数据默认属于客户业务范围，未经授权不得用于跨客户共享或模型训练。

## 13. 开发前待确认事项

- 首批用户是谁，是否已有可参与试点的出题人和领域审核者？
- 首批资料是什么格式，主要以文本、表格、公式还是扫描件为主？
- 是先做“出题与导出”，还是必须包含在线考试？
- 哪些题型和导出格式是第一版必需的？
- 哪些资料可以发送给外部模型，是否需要私有化部署？
- 如何评估题目质量、审核工作量和试点结果？

建议在上述问题明确后，再编写详细需求、数据库设计、接口协议与实施任务清单。
